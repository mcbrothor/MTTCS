# MTN UI·중복 기능 최적화 구현 결과

작성일: 2026-09-09 · 작업 브랜치: `codex/mtn-ui-optimization`

현재 구현의 다크 테마, 8개 핵심 메뉴, 6개 전문 스캐너, 7개 투자 전략을 유지하면서 리뉴얼 계획의 UI·중복 기능 최적화 단계를 적용했다. 운영 브랜치의 종가베팅 시초 성과 기능을 먼저 병합한 뒤 변경했다. 운영 배포 전 로컬 검증 결과다.

## 적용 내역

| 계획 | 구현 결과 |
|---|---|
| D01 복기 탐색 | 본문에서 반복되던 탭을 공통 하위 탐색으로 통합. 시장·카테고리·추천일을 보존하고, 추가 쿼리가 있을 때 활성 탭이 풀리던 문제 수정. 실제 매매 복기에 추천일 필터가 적용되지 않는 이유 표시 |
| D02 교차 보기 | `/scanner?view=cross-check`에 ‘여러 스캐너 포착’ 통합. `/cross-check`는 유니버스를 유지하는 호환 경로. 실제 6개 저장 키를 연결하고 누락·형식 오류·저장 시각·소스별 포함 기준 제공. 서로 다른 거래소의 동일 티커를 분리 |
| D03 오늘 | 하단의 반복 경로 5개 제거. 다음 행동 문구에 ‘시작하기’를 중복 첨가하지 않음 |
| D04 후보 선택 | 미너비니·CAN SLIM의 겹치는 부유 CTA를 하나의 공통 선택 바로 통합. 결과 목록 위에 배치하고 스크롤 시 상단에 유지. 선택 수·전체 해제·콘테스트 이동 제공. 상세 모달에서는 숨김 |
| D05 스캐너 조작 | 6개 유니버스 선택기, 표/카드 보기가 있는 5개 엔진의 보기 선택기를 공유. 엔진별 점수·전문 열·필터·상세 근거 유지. CAN SLIM→콘테스트의 저장소 불일치 수정 |
| D06 관심종목 분석 | 메모 편집과 분석 조회를 분리. ‘종목 분석 보기’로 요청하고 실패 시 재시도. 종목 식별값이 같으면 메모 저장으로 재조회하지 않음. Stock360과 요청 공유기·응답 검증기 재사용 |
| D07 추천 요약 | 이력 외 화면에서는 빈출 요약을 펼칠 때만 조회. 장문 성과 기준을 접고 가격수익률·비용·D5/D20/D60 기준은 요약에 유지 |
| D08 종가베팅 | 후보/익일 시초 성과 분리, 시장별 빈 상태 한 개, 보류 사유 노출. 같은 스냅샷으로 요약·상세를 표시. NXT 08:05·KRX 09:05와 기존 개장+30분 가상 평가를 별도 표시 |
| D09 보조 메뉴 | 데스크톱 보조 링크 4개를 도움말·관리 두 메뉴로 묶음. 직접 URL, 모바일 전체 메뉴, 키보드 닫기 유지 |
| D10 미참조 코드 | 사용처 검색과 빌드 확인을 거쳐 ScannerTabNav·LifecycleStepper 제거. 기존 별칭 redirect 유지 |
| D11 조회 최적화 | 같은 매크로 요청 공유, 성공 응답 30초 재사용, 한국/미국 키 분리. 다른 구독자가 있으면 요청 유지하고 마지막 구독 취소 시 중단. 모바일 숨김 시세 조회 중단, 저장 화면 펼침 시 로딩, Stock360 취소 처리·차트 코드 지연 로딩 |

## 검증에서 확인한 동작

- 브라우저에서 데스크톱 매크로 페이지·Provider·상단 시세가 합계 1회 조회했다. 모바일 추천 화면의 숨겨진 시세 조회는 0회였다.
- 성과 화면에서 빈출 요약을 펼치기 전 조회 0회, 펼친 뒤 1회였다.
- 관심종목을 열어 메모를 편집할 때 분석 조회 0회, 분석을 직접 요청한 뒤 메모를 저장해도 추가 조회 0회였다.
- 종가베팅 후보/성과 전환 시 추가 스냅샷 조회 0회였다. 날짜 전환·이전 응답 무시·시간 초과·재시도도 검증했다.
- 교차 보기는 앞의 3개 엔진에만 있는 종목과 뒤의 3개 엔진에만 있는 종목을 모두 보존했다. 진입 시 스캔 요청은 0회였다.
- 360px·375px·390px 화면, 200% 확대, 키보드 이동, axe serious/critical 접근성 기준을 검증했다. 선택 바가 두 개 생기지 않고, 데스크톱 초기 배치에서 결과 표와 겹치지 않음을 확인했다.

검증 명령과 최종 결과는 아래 완료 기록을 참조한다. 테스트는 고정 응답을 사용한 기능·조회 횟수 검증이며 운영 p95 응답시간이나 서버 처리량 측정은 아니다.

## 데이터와 전환 범위

교차 보기는 현재 브라우저에 저장된 스냅샷을 사용한다. 모멘텀·쿨라매기·전환 초입의 교차용 저장은 업데이트 후 완료한 수동 스캔부터 생성된다. 과거 서버 결과의 자동 소급 수집은 하지 않는다. 기존 CAN SLIM의 양수 SEPA 통과율 60 미만 제외 규칙을 그대로 유지했으며, 포착 횟수를 매수 등급으로 해석하지 않는다.

콘테스트 이동 바는 현재 후보 입력 계약이 구현된 미너비니와 CAN SLIM에 적용한다. 주도주의 기존 선택 저장 기능은 유지하며, 주도주 결과를 콘테스트 평가 입력으로 변환하는 확장은 후속 범위다.

각 전략의 판정 알고리즘, 발행·철회·평가 스케줄, 기존 거래 원장과 저장 증거는 유지했다. 매크로 캐시는 브라우저 메모리에만 존재하며 원래 데이터 기준시각을 바꾸지 않는다. Stock360과 관심 분석은 요청 옵션이 다르면 별도 요청으로 처리한다.

전체 리뉴얼 로드맵의 백엔드 구조 개편·대규모 처리량 개선은 후속 단계다. 이번 적용으로 운영 성능이 ‘최고’라고 판정하거나 절감률을 추정하지 않는다.

## 완료 기록

- `npm test`: **192개 테스트 파일 통과**.
- `npm run lint`, `npm run typecheck`, `npm run check:api-auth`: 통과.
- `NEXT_DIST_DIR=.next-verify npm run build`: 프로덕션 빌드 통과.
- 접근성·복기·종가·조회 최적화 인수 테스트: **31/31 통과**.
- 콘테스트·전체 사용 흐름·스캐너 회귀: **20/20 통과**.
- 추천 성과, 오늘, 매크로, 반응형 기존 테스트도 해당 실행에서 통과. 변경 전 버튼을 찾던 테스트는 단일화된 탐색 계약으로 수정했고, 분석 응답 형식 오류·스캔 버튼 대비 부족은 코드에서 수정했다.
- 최종 실제 화면 캡처 및 선택 바 겹침 검증: **2/2 통과**. 캡처 파일은 위 경로에 보관했다.

작업 트리의 변경을 검증했으며 운영 배포·운영 DB 변경·실제 주문·메시지 발송은 수행하지 않았다.
