# 국내 종가베팅 V1

기존 `getScannerUniverse('KOSPI200'|'KOSDAQ150')` 풀을 그대로 사용한다.
현재 이 풀은 코스피 시총 상위 200개·코스닥 시총 상위 150개이며 지수 구성종목 목록과 같다고 가정하지 않는다.
시세는 KIS KRX 기준, 시장별 적격 최대 5종목이다. 적격 종목이 부족하면 빈자리를 유지한다.

## 사용자 흐름

`국내 전략 → 종가베팅`에서 LIVE/REPLAY와 거래일을 선택한다.
LIVE 관찰 후보, 마감 전 공식 추천, 과거 재현 검토본을 구분한다.
시장별 상태·수집률·점수·거래대금·진입 범위·무효화 가격·수급 시각을 확인하고
펼침 영역에서 분봉·점수 항목·공시와 익일 가상 성과를 검토한다.
웹과 텔레그램은 같은 불변 FINAL 스냅샷을 사용한다.

## 선정 정책

- 설정: `lib/closing-bet/config.ts`. 500억원, 75점, 최대5개, 동일 업종 최대2개.
- 배점: 후반25·유동성20·차트15·수급15·재료10·체결10·과거 움직임5.
- 가격위치, VWAP, 후반 상대강도, ATR 이격, 거래 상태·호가·분봉 신선도를 검사한다.
- 당일 실제 돌파 실패는 제외하되, 아직20일고가를 돌파하지 않았다는 이유만으로 제외하지 않는다.
- 같은 시각20일 상대거래량은 완성 분봉 누적거래량으로만 계산한다. 일봉 총거래량을 선형 역산하지 않는다.
- 입력 결측은 0 순매수로 바꾸지 않고, 가중치를 재분배하지 않는다.
- 지수 대용 ETF069500/229200의 KRX 분봉으로 시장별 후반 강도와 VWAP 위치를 측정한다.
  대용 지표임을 화면·스냅샷 경고에 기록한다. 기준 데이터가 없으면 공식 추천을 차단한다.
- 전 종목 기본 데이터를 확인하고 거래대금 적격 상위35개를 상세 분석한다. 이 처리 범위를 명시한다.
- 공시 목록은 게시 날짜만 알려주는 경우가 있다. 과거 공시는 해당일 종료 이후 알려진 것으로 보수적으로 취급하며
  당일 공시는 최초 수집시각 이전에 알려진 것으로 소급하지 않는다. 공시 제목만으로 실적 개선을 단정하지 않는다.

## 시점·재현 계약

LIVE는 당일만, REPLAY는 과거15:18(특별장 마감12분전)까지의 완성 분봉과 전일까지의 일봉을 사용한다.
KIS 과거분봉 응답의 output1은 현재값이므로 역사 재현에 사용하지 않는다.
누적거래대금 필드는 인접 분봉 누적값의 차로 변환하여 합산하며, 가격×거래량으로 실측 거래대금을 가장하지 않는다.
과거 호가·장중 가집계·종목 상태·당시 풀 편입을 검증할 수 없으면 REPLAY로만 발행한다.
REPLAY의 `picks`는 비어 있고 `reviewCandidates`에 검토 순위를 둔다. 실전 성과 집계에 섞지 않는다.

## 운영 시각

스케줄러 소유자는 기존 Supabase pg_cron이며 Vercel crons를 추가하지 않는다.
UTC 트리거는 일반장과 특별장 범위를 포함하고 각 핸들러가 한국 거래일과 세션 시각을 재검증한다.
이 경로만 HTTP 대기 240초·응답 수집 300초를 적용한다. 기존 작업의 55초·120초 제한은 유지한다.

| 단계 | 동작 |
|---|---|
| prepare | 장중 마감60분전까지 일봉·20일 상대거래량 기준선 준비. 시간 제한에 따라 다음 배치에서 이어서 진행 |
| watch | 오후15분 간격 관찰 결과 저장. 텔레그램 공식 추천으로 전송하지 않음 |
| final | 마감13분전부터 수집,12분전 완성 분봉 확보, 종가 단일가 시작 전까지 발행 |
| monitor | 종가 단일가 및 종가 확인 구간에서 가격 상한·무효화·거래 상태 변경 알림 |
| review | 다음 거래일 개장30분 이후 사전 규칙의 가상 성과와 복기 알림 |

일반장은15:18발행 목표,15:20이후 늦은 추천 전송 금지다. 데이터가 늦거나 검증에 실패하면 공식 추천을 차단한다.
휴장 조회는 DB 일별 캐시를 사용한다. 특별 개장/마감은 `CLOSING_BET_SESSION_OVERRIDES_JSON`으로 공식 일정을 반영한다.
초기 기준선 준비가 끝나기 전에는 해당 점수의 가점이 없으며 선정 수를 맞추기 위해 정책을 낮추지 않는다.

## 저장·발송

- 신규 테이블: closing_bet_snapshots/cache/deliveries/evaluations/locks.
- 모든 테이블 RLS 활성화, anon/authenticated 접근 금지, 서버 service_role만 접근한다.
- FINAL은 거래일·시장·모드·단계·버전당 한 발행. 재실행은 기존 결과를 반환한다.
- 발송 고유키: 스냅샷·채팅 해시·메시지 종류·조각 번호.
- 확정 실패만 재시도. 네트워크 응답 유실이나 전송 후 영수증 장애는 UNCERTAIN으로 자동 재전송을 중단한다.
- 캐시는 만료 후 정리하며 공식 추천·발송·성과 이력은 보존한다. 과거 기준선은 집계값만 저장한다.
- 신규 진입 보류 알림은 이미 체결된 주문을 취소하는 기능이 아니다. 실주문은 실행하지 않는다.

## 검토용 실행

Node24와 저장소 `.env.local`의 기존 KIS/Supabase/Telegram 설정을 사용한다.
기본은 dry-run이다. `--write`는 저장, `--send`는 실제 발송을 명시한다. `DRY_RUN=true`는 발송·DB 쓰기를 막는다.

```bash
node --env-file=.env.local scripts/run-closing-bet.mjs --date=2026-09-03 --mode=REPLAY --write --collect-baselines --evaluate
node --env-file=.env.local scripts/run-closing-bet.mjs --date=2026-09-03 --mode=REPLAY --action=send --write
```

같은 명령의 날짜를2026-09-04로 바꾸면 해당일 검토본을 만든다.
검토본은 `tmp/closing-bet/`에 JSON과 텔레그램 원문으로 남는다.
원문·품질·조건·종목을 검증한 후 발송한다. `--action=send` 재실행은 성공 영수증을 존중한다.

## 성과 해석

KRX 종가→익일 시가 비교와 조건부 진입·익일 개장30분후 시간청산의 시뮬레이션을 분리한다.
비용은 왕복25bp 가정이며 실제 계좌의 수수료·세금 추정이라고 표시하지 않는다.
갭으로 손절가를 지나면 가능한 시가를 적용한다. 같은 분봉에서 목표와 손절을 모두 접촉하면 손절을 우선한다.
분봉 경로가 누락되면 DATA_MISSING, 다음 거래일이 아직 지나지 않았으면 PENDING이다.
실제 주문·호가 순번·부분 체결은 검증하지 않았으므로 실제 투자자 수익률이라고 표시하지 않는다.

## 배포 검증

엔진·평가·KIS·화면·텔레그램·스케줄 테스트, lint/typecheck/build/API auth audit를 실행한다.
마이그레이션과 manifest를 포함하는 깨끗한 커밋에서 `scripts/release/verify-release.mjs --verify-clean-clone`을 통과한 후 배포한다.
배포 후 `/api/release` SHA와 모든 cron endpoint의 인증 없는401 응답을 확인하고 신규 스케줄을 적용한다.

### 기준일 전환 회귀 검증

날짜·모드 필터는 History API로 URL과 클라이언트 조회를 함께 갱신한다. 서버 페이지 전환을 기다리지 않으며, 조회 중에도 날짜 목록을 유지한다. 응답·오류는 날짜·모드·새로고침 키가 일치할 때만 표시하고, 이전 요청은 취소한다. 전체 조회가 15초를 넘으면 재시도 안내를 표시한다.

`tests/e2e/closing-bet-navigation.spec.ts`는 페이지 전환 지연 시 9월 4일→3일→4일 선택, 빠른 연속 선택, 오류 후 재시도, 응답 시간 초과를 검증한다. 기존 Playwright 인증 환경에서 다음 명령으로 실행한다.

```bash
npm run test:e2e -- tests/e2e/closing-bet-navigation.spec.ts
```
