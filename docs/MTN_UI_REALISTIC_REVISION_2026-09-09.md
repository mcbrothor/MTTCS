# MTN 실제 UI 기반 리뉴얼 수정안

검토일: 2026-09-09 · 운영 화면 직접 관찰 및 로컬 코드 대조 · 구현 전 화면 제안

## 1. 수정 결론

기존 네이비 다크 테마, MTN 로고·종목 검색·시장 지표, 상단 가로 메뉴, 스캐너별 전문 표와 큰 차트를 유지한다. 처음 제시한 밝은 카드형 화면과 좌측 5개 메뉴 시안은 현재 화면의 구성·정보 밀도·전문 도구를 충분히 반영하지 못했으므로 폐기한다.

이번 1차 개선은 **결과를 먼저 보이게 하는 배치, 한 곳에서 처리하는 후보 선택, 명확한 기준시각·보류 사유**에 집중한다. 5개 작업 영역은 기능 소유권 분류로만 남기며 메뉴 통합의 확정안으로 사용하지 않는다.

이 문서는 [전체 계획](/Users/mantori/vibecoding/MTN/docs/MTN_RENEWAL_PLAN_2026-09-05.md)과 [UI·성능 상세안](/Users/mantori/vibecoding/MTN/docs/MTN_UI_PERFORMANCE_BLUEPRINT_2026-09-05.md)의 초기 UI 배치 결정을 수정한다. 운영 UI 구현·배포 완료를 뜻하지 않는다.

## 2. 실제 확인 범위와 한계

사용자가 로그인한 Chrome의 운영 `mttcs.vercel.app`을 열고 화면·접근성 트리·상호작용을 확인했다. 화면 크기는 약 1905×811이었다. 기존 후보 선택은 14/15였으며 스캔 실행·선택 변경·텔레그램 전송·계획 저장은 수행하지 않았다.

스캐너의 화면 표시 `Last scan`은 **2026-08-26 01:05:23**이었다. 시장 요약 갱신 시각과 개별 스캔의 기준일은 다르다. 이번에는 표시값의 불일치를 관찰했으며 시세 원천·현재 추천 적격성 자체를 재검증하지 않았다.

종가베팅은 9월 9일과 9월 8일의 실전 기록을 확인했다. 시안은 **9월 8일 과거 기록**을 기준으로 삼는다. 코스피는 시장 미확인·수집200/200·실패0·추천 보류, 코스닥은 시장 위험·수집149/150·실패1·추천 보류였고 양쪽 모두 선정0/5였다. 코스피 확인 사항3건은 상세 분석 상위35개, ETF069500 대용, 시장 미확인 보류였으며 코스닥2건은 ETF229200 대용, 시장 위험 보류였다.

검토 중 로컬 HEAD는 `be70c6e`였다. 운영의 NXT/KRX 시초 성과 영역은 읽은 로컬 `ClosingBetDashboard.tsx`와 달랐다. 따라서 9월 5일 코드와 현재 운영 UI를 같은 버전으로 간주하지 않는다. 이번 관찰만으로 새 평가 계산·DB·발송·모든 34개 화면·모바일 동작을 검증했다고 주장하지 않는다.

## 3. 현실적인 화면 변경안

### A. 미너비니 스캐너

1. 현재 공통 헤더와 6개 엔진 탭을 유지한다.
2. 큰 제목/설명/설정 카드를 압축한다. 4개 유니버스·표/카드·스캔 시작을 도구 모음에 놓고 설명은 한 줄과 도움말로 정리한다.
3. Master Filter와 Macro Action은 한 줄에 두되 서로 다른 판정임을 표시한다. 하나의 새 점수로 합산하지 않는다.
4. 결과·Recommended·Near-miss·Action·IB Review·오류·원천 정보를 낮은 요약 줄로 정리한다. 저장된 보기, 이전 스캔 대비, 필터·정렬 기능을 유지한다.
5. 저장된 스캔의 날짜와 데이터 기준을 결과표 바로 위에 표시한다. 시장 요약의 갱신 시각을 스캔의 신선도로 오인하게 하지 않는다.
6. 전문 표의 전체 폭과 모든 기존 열을 유지한다. 첫 화면에서 실제 결과 행을 볼 수 있게 한다. 100개를 모두 한 화면에 억지로 넣지 않는다.
7. 두 콘테스트 부유 버튼을 **한 개의 후보 행동 바**로 통합한다. 선택 수·해제·텔레그램·콘테스트 이동은 같은 선택 상태를 사용한다. 바의 공간을 확보하여 표를 가리지 않고 모달이 열리면 뒤의 바는 비활성화/숨김 처리한다.

### B. 종가베팅

1. 한국 전용 표시, 실전 스냅샷/과거 재현·검토, 기준일·새로고침, 두 시장 Top5를 보존한다.
2. 제목·설명 영역을 줄이고 `추천 후보 / 익일 시초 성과` 로컬 탭을 둔다. 후보 화면에도 짧은 성과 요약과 상세 연결을 남긴다. 탭은 같은 날짜·모드·원본을 공유한다.
3. 두 시장의 선정 상태·시장 상태·수집률·기준시각·보류 사유가 먼저 보이게 한다. 0개일 때는 미선정 5행을 반복하지 않고 하나의 빈 상태를 사용한다.
4. 후보가 있으면 현재의 순위·점수·현재가/등락률·거래대금·상위 근거·진입 상한·무효화·수급을 보존한다. 미니 차트·점수 세부·VWAP/RVOL·스프레드·만료·증거 링크는 펼침으로 제공한다. 이번 이미지의 0개 상태를 후보가 있는 화면의 삭제 설계로 해석하지 않는다.
5. 시초 성과의 가격 기준은 추천일 KRX 종가와 익일 **NXT 08:05 / KRX 09:05로 표시된 각 1분봉 종가**, 왕복25bp 가정이다. NXT 미거래·분봉 누락은 미확인, 선정0개는 미평가다. 실제 계좌 체결·기존 개장+30분 평가와 혼합하지 않는다.

![현재 화면을 참고한 종가베팅 배치 시안](/Users/mantori/vibecoding/MTN/docs/assets/ui-review-2026-09-09/closing-bet-refinement.png)

두 이미지는 운영 캡처를 참조해 내장 이미지 생성 도구로 제작한 **배치 검토용 시안**이다. 구현된 화면이나 현재 추천 결과가 아니다. 이미지 생성 과정의 세부 글자·시세 재현은 데이터 계약의 근거로 사용하지 않는다. 예를 들어 스캐너 이미지의 KOSPI 등락 표기는 운영에서 읽은 +1.40%를 원본으로 삼고, 종가 이미지 코스닥 확인 사항에는 운영에서 확인한 2건만 연결한다. 실제 문구·값·동작의 기준은 위 관찰 기록과 원본 응답이다. [생성 프롬프트](/Users/mantori/vibecoding/MTN/docs/assets/ui-review-2026-09-09/prompts.md)를 함께 보관한다.

### C. 차트와 쿨라매기 근거

현재 큰 패턴 차트의 크기와 도구를 유지한다. 차트 보기 클릭 시 즉시 차트 영역을 제공하고 자료 로딩은 그 안에서 표시한다. 닫기·Escape·초점 복귀를 일관되게 구현한다. 스캐너 저장 분석의 기준시각과 차트 가격의 기준시각이 다르면 각각 명시한다.

쿨라매기는 로컬의 `evidenceRef.snapshotId`와 `QullamaggieEvidenceModal`을 확인했다. 동일 시세 스냅샷과 판정 근거가 연결된 현재 구조를 보존하고, 공통 차트화 때문에 최신 데이터로 과거 셋업 근거를 바꾸지 않는다. 이번에는 쿨라매기 운영 결과 전체를 직접 검증한 것은 아니다.

## 4. 구현 순서와 성능 검증

| 단계 | 변경 | 완료 판단 |
|---|---|---|
| 1. 화면 기준선 | 같은 날짜·모드·선택 상태로 현재 화면/요청 수/전송량/첫 결과까지 스크롤 기록 | 운영·로컬 버전과 데이터 시점 차이를 식별하고 비교 조건을 고정 |
| 2. 배치 | 스캐너 상단 압축·한 개 선택 바, 종가 후보/성과 탭·빈 상태 | 기존 열·필터·원본 링크·14/15 선택·두 시장 상태 보존, 같은 화면 크기에서 첫 결과가 보이고 겹침 없음 |
| 3. 데이터 조회 | 요약/목록/차트/성과 조회 경계와 공통 key·진행 중 요청 공유 | 필터·정렬만으로 원천 재수집하지 않음. 요약과 성과 탭은 같은 결과를 재사용. 닫힌 차트는 불필요하게 로드하지 않음 |
| 4. 측정·전환 | 동일 데이터로 브라우저/서버/작업 지연·메모리·오류율 비교 | 기존 UP01~UP10의 정확성·신선도·응답 목표 충족. 계측 없이 최고 성능·절감률을 주장하지 않음 |

탭을 분리했다고 서버의 익일 평가 작업까지 중단해서는 안 된다. 브라우저는 필요한 결과만 조회하고 발행·철회·평가 일정은 서버가 관리한다. 차트 UI의 공유, 원천 OHLC 공유, 전략 판정 결과의 공유는 각각 입력·시점·정책이 같은지 따로 검증한다.

기존 전체 로드맵의 2~5주 UI 작업 범위에서 단계2를 우선한다. 가로 메뉴를 5개로 합치거나 차트 라이브러리·프레임워크를 교체하는 일은 이번 1차 개선의 선행 조건이 아니다. 모바일 360px·200% 확대·키보드·선정0/일부/5개·데이터 지연/누락·과거/LIVE 전환을 구현 인수에 포함한다.

## 5. 이번 산출물 검증

- 운영 화면과 접근성 정보에서 메뉴, 스캐너 전문 열, 실제 선택 수, 기준일, 두 시장의 보류·수집 상태, NXT/KRX 성과 설명을 대조했다.
- 두 시안에서 가로 탐색·기존 색상·전문 표 또는 Top5 두 열이 유지되는지 육안 검토했다. 작은 문구/수치의 이미지 재현 한계는 위에 구분했다.
- 변경 범위는 계획 문서와 이미지 시안이다. 운영 코드·DB·스캔·발송·거래 기록을 변경하지 않았다. 실행 코드 테스트와 성능 부하 실험은 이번 문서 작업에서 재실행하지 않았다.
