# MTN StockEasy 도입 기능 최종 선별

> 기준일: 2026-06-20  
> 입력: StockEasy 벤치마킹 후보 158개, MTN 현재 코드·데이터·운영 구조  
> 목적: 실효성, 개발 효율, 투자대비 효과, 유지비, 데이터 위험을 반영해 실제 도입 가치가 높은 기능만 남긴다.

## 1. 최종 결론

도입 권고 기능은 8개다. 이 중 7개는 기존 MTN 자산을 크게 재사용할 수 있으며, 마지막 `Daily Brief`는 앞선 기능이 만든 데이터를 재조합하므로 후순위 비용도 낮다.

| 순위 | 기능 | 총점 | 예상 공수 | 판단 |
|---|---|---:|---:|---|
| 1 | 데이터 신뢰 계층 | 97 | 1.5~2.5 인주 | 필수 선행 |
| 2 | 저장형 스크리너 + 오늘의 변화 | 95 | 2~3 인주 | 즉시 도입 |
| 3 | 전역 검색 + 종목 360 MVP | 92 | 4~6 인주 | 즉시 도입 |
| 4 | 관심종목 Cockpit + 알림 엔진 | 92 | 4~5 인주 | 즉시 도입 |
| 5 | 공시·실적 이벤트 리스크 | 91 | 3~4 인주 | 즉시 도입 |
| 6 | 설명 가능한 Market Now | 85 | 3~4 인주 | 2차 도입 |
| 7 | Sector Leadership | 81 | 4~6 인주 | 2차 도입 |
| 8 | US → KR Daily Brief | 80 | 2~3 인주 | 조건부 도입 |

한 명이 순차 구현하면 약 24~34 인주다. 공통 데이터 계약과 UI 컴포넌트를 먼저 만들면 중복을 줄여 약 20~27 인주까지 압축할 수 있다.

공수는 현재 코드에 익숙한 시니어 풀스택 엔지니어 1명 기준이며, 외부 데이터 구매·계약 기간과 대규모 과거 데이터 백필은 제외했다.

가장 높은 투자대비 효과는 `새 화면 수`가 아니라 다음 세 흐름에서 나온다.

1. 매번 다시 스캔·검색·확인하는 시간을 줄인다.
2. 공시·실적·데이터 노후화로 인한 오판을 줄인다.
3. 발견한 후보를 관심종목·콘테스트·매매 계획으로 바로 연결한다.

## 2. 평가 방식

각 항목을 10점 척도로 평가하고 다음 가중치를 적용했다.

```text
총점 = 실효성 30% + 구현 효율 20% + 투자대비 효과 25%
     + MTN 전략 적합성 15% + 데이터·운영 실현성 10%
```

| 평가축 | 판단 기준 |
|---|---|
| 실효성 | 투자 판단의 정확도·속도·위험 통제에 직접 영향을 주는가 |
| 구현 효율 | 현재 API, DB, 엔진, 컴포넌트를 재사용할 수 있는가 |
| 투자대비 효과 | 개발·데이터·운영비 대비 반복적으로 큰 가치를 만드는가 |
| 전략 적합성 | MTN의 `시장→발굴→검증→계획→리스크→복기`를 강화하는가 |
| 실현성 | 신뢰 가능한 데이터와 지속 가능한 운영 구조가 있는가 |

선정 기준은 80점 이상이다. 80점 미만은 기능이 나쁘다는 의미가 아니라, 현재 MTN에 투자할 순서가 아니라는 뜻이다.

## 3. 선별 기능

### 3.1 데이터 신뢰 계층

**선정 이유**

- 모든 후속 기능의 오류 비용을 낮춘다.
- `lib/data/freshness.ts`, `stock_metrics` stale guard, admin data health가 이미 있어 재사용률이 높다.
- 오래된 데이터를 최신 데이터처럼 보고 매매하는 가장 비싼 오류를 방지한다.

**도입 범위**

- 모든 핵심 값에 `source`, `observedAt`, `fetchedAt`, `calculatedAt`, `isStale`, `fallbackReason` 표시
- `PRIMARY`, `FALLBACK`, `PARTIAL`, `UNAVAILABLE` 품질 상태
- stale 필수 입력이 있으면 점수 대신 `판정 보류`
- 투자 화면과 admin health의 원천 상태 대사

**제외 범위**

- 전체 데이터 파이프라인 재작성
- 사용자가 이해하기 어려운 provider 로그 직접 노출

**효과**

- 잘못된 자동 판단의 하방 위험 감소
- 장애 조사 시간 단축
- 이후 Market Now, 종목 360, Brief의 신뢰 기반 확보

### 3.2 저장형 스크리너 + 오늘의 변화

**선정 이유**

- MTN은 이미 5개 전문 스캐너를 보유하므로 신규 분석 엔진이 필요 없다.
- 반복되는 필터 조작과 전체 재검토를 줄이는 가장 저렴한 생산성 기능이다.
- `stock_metrics` 히스토리와 일일 스크리너를 활용하면 진입·이탈 diff를 계산할 수 있다.

**도입 범위**

- 시장, 엔진, 등급, RS, VCP, 위험 상태, 유동성 중심의 공통 필터
- 이름을 붙인 필터 저장과 URL 재현
- 전일 대비 `새 진입`, `이탈`, `등급 상승`, `등급 하락`
- 저장 필터 결과에서 관심종목·콘테스트·계획으로 이동
- 장마감 기준 진입·이탈 알림 준비

**제외 범위**

- 데이터가 안정적으로 없는 30여 개 재무·수급 필터의 일괄 도입
- 사용자가 이해할 수 없는 자유 수식 빌더

**효과**

- 매일 후보 검토 시간을 크게 단축
- 기존 스캐너의 사용률과 가치 상승
- 신규 스캐너 개발 없이 제품 체감 개선

### 3.3 전역 검색 + 종목 360 MVP

**선정 이유**

- 후보를 찾은 뒤 여러 화면과 외부 사이트를 오가는 비용을 줄인다.
- `security-lookup`, `price-history`, DART, SEC, `fundamental_cache`, scanner 결과를 재사용할 수 있다.
- 검색은 모든 페이지의 공통 진입점이므로 사용 빈도가 높다.

**도입 범위**

- `Ctrl/Cmd+K` KR/US 종목 검색과 최근 검색
- 가격 차트, RS와 RS Line, 핵심 재무, 데이터 품질
- DART/SEC 공시 요약과 최신 제출 시각
- 해당 종목의 스캐너 통과·탈락 근거
- 관심종목, 콘테스트 추가, 매매 계획 CTA

**제외 범위**

- 증권사 리포트 원문·목표주가 전체 수집
- 범용 뉴스 포털
- 사용자별 임의 지표 배치 편집
- ETF 전체 상세 허브

**효과**

- 후보 발견에서 계획 수립까지 이동 횟수 감소
- 외부 정보 확인 누락 감소
- 기존 엔진과 데이터의 노출 가치 상승

### 3.4 관심종목 Cockpit + 알림 엔진

**선정 이유**

- 현재 watchlist CRUD와 Telegram cron을 확장하면 된다.
- 후보를 저장하고도 다시 보지 않는 문제를 해결한다.
- 피벗·손절·공시·스크리너 변화는 실제 행동으로 이어질 가능성이 높다.

**도입 범위**

- 관심 그룹, 수동 우선순위, 이름·등락·RS 정렬
- 마지막 가격·RS·스캐너 상태 변화 배지
- 피벗 근접, 손절 근접, 52주 고점 근접, 돌파, 저장 필터 진입·이탈 규칙
- 공통 cooldown과 중복 억제
- 인앱 알림함과 Telegram 채널 설정

**제외 범위**

- 초기 브라우저 푸시와 다기기 관리
- 소셜 공유와 공개 관심종목
- 지나치게 많은 가격 변동 알림

**효과**

- 관심종목의 실제 계획 전환율 증가
- 손절·이벤트 위험 대응 속도 개선
- 별도 앱 없이 현재 Telegram 인프라 활용

### 3.5 공시·실적 이벤트 리스크

**선정 이유**

- 좋은 차트도 공시·실적 직전에는 gap risk가 커진다.
- DART corp code, DART provider, SEC EDGAR, fundamental cache가 이미 구현되어 있다.
- 수익을 약속하는 기능이 아니라 큰 손실을 방지하는 기능이라 실효성이 높다.

**도입 범위**

- DART/SEC 최신 공시의 중요도 분류
- 실적 발표일과 주요 경제 이벤트를 계획·포트폴리오에 표시
- 이벤트 임박 시 신규 진입 경고와 sizing 축소 제안
- 관심종목·활성 포지션에 핵심 공시 알림
- 판단 당시 이벤트 snapshot을 복기에 보존

**제외 범위**

- 라이선스가 필요한 증권사 리포트 전체 수집
- 모든 뉴스를 실시간으로 모으는 범용 피드
- LLM만으로 공시 중요도를 확정하는 구조

**효과**

- 손절 범위를 뛰어넘는 gap loss 위험 감소
- 계획·보유·복기 전 단계에 같은 이벤트 문맥 제공
- 보유 데이터 자산의 사용자 가치 전환

### 3.6 설명 가능한 Market Now

**선정 이유**

- 기존 홈은 다음 행동을 알려주지만 시장 변화의 원인을 빠르게 파악하기 어렵다.
- macro, master-filter, market snapshot, portfolio risk를 재사용할 수 있다.
- 매일 첫 방문 화면의 품질을 높여 전체 제품 사용을 촉진한다.

**도입 범위**

- 주요 지수, 시장 세션, market state, DD, breadth, 오픈 리스크
- 전일 대비 상태 변화 원인 최대 3개
- `신호 변화 → 허용 위험 → 다음 행동` 연결
- MTN 내부 신호·이벤트만 사용하는 간결한 타임라인
- 원천 시각과 stale 상태

**제외 범위**

- 실시간 종합 뉴스 피드
- 원자재·암호화폐·금리 등 모든 지표의 무조건적 나열
- 정보량을 늘리기 위한 카드 추가

**효과**

- 시장 판단 시간 단축
- master-filter와 portfolio risk의 맥락 일치
- 사용자가 잘못된 시장 상태로 계획을 시작하는 문제 감소

### 3.7 Sector Leadership

**선정 이유**

- MTN은 개별 종목 점수는 강하지만 섹터 차원의 참여 폭과 이동을 보여주는 기능이 약하다.
- `stock_metrics`, Leader engine, 시장 snapshots, 포트폴리오 섹터 노출을 재사용할 수 있다.
- 단일 종목이 아니라 주도 그룹을 확인하면 후보 품질과 집중 위험을 동시에 개선한다.

**도입 범위**

- 섹터 1/3/6/12개월 RS와 breadth
- 20일선 위 유지, 대표 종목, 대표 종목의 RS
- 신규 신고가 비중 변화에 따른 유입·유출 추정
- 섹터 참여 종목 수와 집중도
- 시장 주도 섹터와 내 포트폴리오 노출 비교

**제외 범위**

- 출처가 불명확한 테마 자동 생성
- 1분 단위 테마 폴링
- 별도 ETF몰 수준의 섹터 상품 탐색

**효과**

- 리더 종목의 산업 동조 여부 확인
- 같은 위험 요인에 대한 포트폴리오 집중 방지
- scanner, portfolio, review를 연결하는 공통 분류 축 확보

### 3.8 US → KR Daily Brief

**선정 이유**

- 한국장 시작 전 미국장 정보를 다시 해석하는 반복 작업을 줄인다.
- daily screeners, macro snapshot, Sector Leadership 데이터를 재조합하면 된다.
- 독립 데이터 제품이 아니라 앞선 기능의 출력물이므로 후순위 구현 비용이 낮다.

**도입 범위**

- 미국 지수·breadth·주도 섹터·경계 섹터
- KR 후보에 대한 순풍·역풍 매핑
- 강세 관점과 반대 논리 동시 제시
- 기준 시각, 데이터 품질, 사용한 신호 버전
- 발행 당시 판단과 장마감 결과의 사후 비교

**도입 조건**

- 데이터 신뢰 계층과 Sector Leadership이 먼저 완료돼야 한다.
- LLM이 외부 사실을 임의 생성하지 않고 MTN snapshot만 사용해야 한다.

**효과**

- 장 시작 전 준비 시간 단축
- KR/US 시장 전환의 실제 사용자 가치 증가
- 일일 스크리너 후보의 설명력 개선

## 4. 투자 우선순위

### 1차 투자: 가장 빠른 회수

| 묶음 | 기능 | 예상 공수 | 회수 논리 |
|---|---|---:|---|
| A | 데이터 신뢰 계층 | 1.5~2.5 인주 | 잘못된 판단과 장애 조사 비용 즉시 감소 |
| B | 저장형 스크리너 + 오늘의 변화 | 2~3 인주 | 기존 5개 엔진의 반복 사용 효율 극대화 |
| C | 전역 검색 + 종목 360 MVP | 4~6 인주 | 외부 탐색과 화면 이동 시간을 크게 절감 |

1차 투자만으로도 전체 기대 가치의 약 55~65%를 얻을 수 있다. 먼저 여기까지 구현하고 실제 사용 시간을 측정하는 것이 가장 합리적이다.

### 2차 투자: 행동 전환과 위험 감소

| 묶음 | 기능 | 예상 공수 | 회수 논리 |
|---|---|---:|---|
| D | 관심종목 Cockpit + 알림 | 4~5 인주 | 후보의 계획 전환과 위험 대응 증가 |
| E | 공시·실적 이벤트 리스크 | 3~4 인주 | 큰 손실 방지 효과, 기존 DART/SEC 재사용 |
| F | Market Now | 3~4 인주 | 매일 첫 판단 시간과 맥락 오류 감소 |

### 3차 투자: 데이터가 쌓인 뒤

| 묶음 | 기능 | 예상 공수 | 진행 조건 |
|---|---|---:|---|
| G | Sector Leadership | 4~6 인주 | 섹터 분류와 point-in-time metrics 안정화 |
| H | US → KR Daily Brief | 2~3 인주 | A, F, G 완료와 브리핑 품질 평가 통과 |

## 6. ROI 검증 기준

금전 수익을 기능 효과로 직접 주장하지 않는다. 먼저 시간 절감, 위험 회피, 워크플로우 전환으로 투자대비 효과를 검증한다.

| 기능 | 4주 내 검증 KPI | 중단 기준 |
|---|---|---|
| 데이터 신뢰 | stale 판정 누락 0건, 원천 대사 시간 50% 감소 | 상태값이 실제 provider 상태와 반복 불일치 |
| 저장 스크리너 | 반복 스캔의 50% 이상에서 저장 필터 사용 | 사용자가 계속 수동 필터만 사용 |
| 종목 360 | 후보 검토 시간 30% 감소, 계획까지 3회 이하 이동 | 외부 사이트 사용량이 줄지 않음 |
| 관심종목·알림 | 중복 알림 5% 미만, 알림 후 행동률 20% 이상 | 오탐·중복으로 알림을 끄는 비율이 높음 |
| 이벤트 리스크 | 계획·보유 종목 이벤트 누락 0건 | 데이터 지연으로 잘못된 안심 신호 제공 |
| Market Now | 시장 판단 소요시간 30% 감소 | 기존 홈보다 확인 시간이 늘어남 |
| Sector Leadership | 후보 검토의 50% 이상에서 섹터 근거 확인 | 종목 선택 또는 집중 위험 판단에 사용되지 않음 |
| Daily Brief | 장 시작 전 준비시간 30% 감소 | 사실 오류 또는 중복 정보가 반복 발생 |

## 7. 권고 실행 순서

```text
Wave 0: 데이터 신뢰 계층
   ↓
Wave 1: 저장형 스크리너 → 전역 검색 → 종목 360 MVP
   ↓
Wave 2: 관심종목 Cockpit → 알림 엔진 → 이벤트 리스크
   ↓
Wave 3: Market Now → Sector Leadership → Daily Brief
```

각 Wave 완료 후 KPI를 4주간 측정한다. 목표를 달성하지 못하면 다음 기능을 추가하지 않고 기존 기능의 정보 밀도, 데이터 품질, 행동 연결을 먼저 수정한다.

## 8. 최종 판단

MTN에 가장 필요한 것은 StockEasy의 넓은 메뉴가 아니다. **기존의 강한 분석 엔진을 더 빨리 찾고, 더 안전하게 검증하고, 실제 계획으로 전환시키는 기능**이다.

따라서 투자 우선순위는 다음과 같다.

1. 신뢰할 수 있는 데이터
2. 반복 검토를 줄이는 저장형 스크리너
3. 한곳에서 판단을 끝내는 종목 360
4. 행동 시점을 놓치지 않는 관심종목·알림
5. 큰 손실을 피하는 이벤트 리스크
6. 시장과 섹터 문맥을 압축하는 Market Now·Sector Leadership
7. 이미 만들어진 데이터를 재활용하는 Daily Brief

이 8개를 제외한 기능은 현재 시점에서 투자대비 효과가 낮거나, MTN의 핵심 정체성을 흐릴 가능성이 더 크다.
