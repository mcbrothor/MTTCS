# MTN 실시간 시장 인텔리전스 및 투자 성공 확률 고도화 계획

> 기준일: 2026-07-31
> 목표: 수익을 보장하는 자동매매가 아니라, 오래되거나 검증되지 않은 정보로 큰 손실을 내는 경로를 먼저 차단하고 검증된 엣지만 단계적으로 운용에 반영한다.

## 1. 결론

MTN은 전략 수가 부족한 프로그램이 아니다. 이미 시장 판단, 종목 발굴, 매매 계획, 포트폴리오, 복기의 흐름과 다수 전략 엔진을 갖췄다. 지금 투자 성과를 가장 크게 제한하는 요소는 새 스캐너가 아니라 다음 네 가지다.

1. 뉴스·경제지표가 의사결정 시점에 맞춰 수집되지 않고, 원천별 장애가 하나의 성공 상태에 가려질 수 있다.
2. 점수와 추천이 데이터 신선도·검증 커버리지가 부족해도 정상 결과처럼 유통될 수 있다.
3. 포트폴리오 위험 한도가 서버의 단일 권위로 강제되지 않으면 클라이언트 값이나 동시 요청으로 우회될 수 있다.
4. 전략의 과거 설명력과 실제 미래 예측력을 구분하는 point-in-time·walk-forward 검증이 부족하다.

따라서 우선순위는 `데이터 원장 → 신선도 차단 → 검증된 분석 → 서버 리스크 권위 → 성과 귀속` 순서다. LLM은 원문 요약과 반대 논리 생성에 사용하되, 검증 전에는 매수·매도 방향이나 포지션 크기를 직접 결정하지 않는다.

## 2. 이번 구현에서 반영한 기반

### 2.1 공식 원천 실시간 인텔리전스

- Federal Reserve 통화정책 RSS, 한국은행 통화정책 RSS, SEC 거래정지 RSS를 5분 주기로 수집한다.
- BLS CPI·근원 CPI·실업률·비농업 고용은 미국 동부시간 08:30 발표의 서머타임/표준시를 모두 포착하도록 12:35/45/55·13:35/45/55 UTC에 재확인한다.
- 모든 이벤트에 `source`, `externalId`, `publishedAt`, `observedAt`, `firstSeenAt`, `contentHash`, `sourceTier`, 분석 버전을 저장한다.
- 동일 이벤트의 내용이 바뀌면 `(source, externalId, contentHash)` 단위의 새 revision으로 보존하고, 같은 revision의 중복 전달은 무시한다.
- RSS 게시시각이 없으면 이를 공식 게시시각으로 위장하지 않고 `OBSERVED_AT_FALLBACK`으로 표시한다.
- BLS 공식 ICS 캘린더의 발표시각·기대 기준월과 API 최신 기준월을 대조하고, 일치할 때만 성공으로 처리한다. 관측기간 말일과 최초 관측시각도 별도 보존한다.

공식 원천: [Federal Reserve RSS](https://www.federalreserve.gov/feeds/feeds.htm), [BLS Public Data API](https://www.bls.gov/developers/), [SEC Trading Suspensions](https://www.sec.gov/enforcement-litigation/trading-suspensions), [한국은행 RSS](https://www.bok.or.kr/portal/main/contents.do?menuNo=200088).

### 2.2 fail-closed 데이터 품질

- 시장별 필수 원천을 분리한다.
  - US: `FED_MONETARY`, `SEC_TRADING_SUSPENSIONS`, `BLS`
  - KR: `BOK_MONETARY`
- HTTP 200이어도 파싱 결과가 비었거나 BLS 필수 4개 시리즈가 부족하면 성공으로 처리하지 않는다.
- 원천 하나의 최근 요청이 실패하거나 SLA를 넘으면 `Decision readiness = BLOCKED`, 검토용 위험 배수는 `0`이다.
- 화면의 `limit`, `severity`, `eventType`, `since` 필터와 무관한 별도 최근 6시간 위험 조회로 readiness를 계산한다.
- `RISK/WATCH`는 제목·원천 기반 확인 우선순위일 뿐 호재·악재 방향 예측이 아니며, 항상 원문 검토가 필요하다.

### 2.3 매크로·추천·매매 계획 안전장치

- `/api/macro`와 market-state snapshot이 같은 계산 서비스를 사용해 API와 저장값의 산식·시점이 어긋나지 않게 한다.
- 필수 매크로 데이터 커버리지가 부족한 `BLOCKED` 결과는 중립 50점의 정상 데이터로 저장·소비하지 않는다.
- 공식 추천은 전체 후보가 가격 히스토리와 차트 게이트를 통과해야만 발행하고, 검증 부족은 `SHADOW`로 남긴다.
- 계좌자산, 현재 포트폴리오 heat, 섹터 집중, drawdown, 시장 상태는 매매 계획 POST 시 서버에서 다시 계산한다.
- 실시간 인텔리전스의 위험 배수는 현재 `RESEARCH_ONLY / shadow advisory`다. 실증 검증 전에는 기존 포지션이나 주문을 자동 변경하지 않는다.

## 3. 목표 아키텍처

```text
공식·계약 원천
  → source adapter (원문·시각·라이선스 보존)
  → immutable raw/revision ledger
  → dedupe + entity mapping + source health
  → deterministic event classifier
  → async LLM summary / counter-thesis (shadow only)
  → portfolio exposure join
  → readiness / alert / risk advisory
  → 사용자 확인
  → 검증·승인된 규칙만 server risk gate에 반영
```

핵심 계약은 다음과 같다.

| 계층 | 반드시 보존할 값 | 실패 정책 |
|---|---|---|
| 원천 수집 | 원문 URL, 원천 게시시각, 최초 관측시각, fetch 시각, content hash | 원천별 `FAILED/STALE`, 다른 원천 성공으로 덮지 않음 |
| 정규화 | 시장, 이벤트 유형, 기업·티커·주제, revision | 스키마 불일치 시 격리 큐 |
| 분석 | 규칙/모델 버전, confidence, 근거, 한계, 반대 논리 | 방향 불명확 시 `UNKNOWN` |
| 의사결정 | 사용한 입력 revision, 포트폴리오 노출, 적용 정책 | 필수 입력 부족 시 `BLOCKED` |
| 감사 | 사용자 확인, override 이유, 당시 snapshot | 수정 대신 append-only 기록 |

## 4. 추가해야 할 기능 우선순위

### P0 — 실자금 의사결정 전 필수

1. **원천별 Data Health 콘솔과 알림**
   - 최종 성공/실패, 지연, HTTP 상태, 파싱 건수, revision 수, quota 잔량을 한 화면에서 확인한다.
   - 필수 원천 실패, 빈 payload, 지연 SLA 초과를 텔레그램/운영 채널에 즉시 알린다.

2. **트랜잭션 기반 위험 예산 예약**
   - `PLANNED`도 portfolio heat에 예약한다.
   - 계획 생성과 위험 예산 차감을 DB 함수/트랜잭션에서 원자적으로 처리한다.
   - ENTRY 체결 시 같은 게이트를 다시 검사하고, 이미 사용된 예산이나 오래된 계획은 거절한다.

3. **point-in-time 검증 데이터셋**
   - 상장폐지, 기업행사, 수정 전 경제지표, 당시 구성종목을 보존한다.
   - 수수료·세금·슬리피지·호가 공백을 반영한 walk-forward 결과만 모델 승격 근거로 인정한다.

4. **경제 캘린더와 컨센서스 surprise**
   - 실제값만으로 위험 방향을 단정하지 않는다.
   - 공식 발표시각과 계약된 consensus provider의 예상치·이전치·수정치를 결합한다.
   - 공급자 계약 전에는 `surprise = UNKNOWN`을 유지한다.

5. **다중 사용자/계좌 격리 확정**
   - `portfolio_settings`, risk policy, trades, performance snapshot의 owner/account 키를 통일한다.
   - 현재 단일 운영 계정 전제를 유지한다면 제품과 운영 문서에 명시한다.

### P1 — 알파 탐색과 운용 효율

1. **기업·티커 entity graph**
   - SEC CIK, OpenDART corp code, 거래소 ticker, 회사명 별칭을 하나의 security ID로 연결한다.
   - 뉴스·공시를 보유종목, 관심종목, 같은 섹터·공급망에 매핑한다.

2. **미국·한국 공시 이벤트**
   - SEC 8-K/10-Q/10-K/13D/13G/Form 4와 OpenDART 주요사항보고서를 우선 수집한다.
   - 증자, 전환사채, 내부자거래, 감사의견, 실적 가이던스 변경을 구조화한다.

3. **계약형 실시간 뉴스 adapter**
   - 웹스크래핑이 아니라 webhook/WebSocket·재배포 권한·과거 보존 권한이 명확한 공급자를 선정한다.
   - 평가 기준은 US/KR 커버리지, p95 지연, ticker 정확도, correction 지원, 호출 한도, 원문 링크, 저장 라이선스다.
   - 공급자 장애 시 공식 공시·중앙은행 원천은 계속 동작하고 종합 뉴스만 `DEGRADED`로 표시한다.

4. **포트폴리오 이벤트 레이더**
   - 실적, FOMC/CPI, lock-up, 옵션 만기, 배당락, 공매도·거래정지 이벤트를 포지션별 달력으로 보여준다.
   - 이벤트 전 예상 gap risk와 손절가를 넘는 손실 가능성을 별도 경고한다.

5. **성과·의사결정 귀속**
   - 수익을 종목선정, 시장 regime, 진입, sizing, pyramid, exit, 섹터, 환율로 분해한다.
   - 추천 당시 confidence 구간별 실제 적중률을 측정해 calibration을 교정한다.

### P2 — 검증 후 차별화

- 사건 전후 abnormal return, volatility, liquidity 변화의 event study
- 같은 이슈를 다르게 보도하는 출처 간 모순 탐지
- 포트폴리오 factor/correlation cluster 및 스트레스 시나리오
- 사용자별 실수 패턴에 맞춘 pre-trade checklist 강화
- LLM counter-thesis와 “이 판단이 틀릴 조건” 자동 생성

## 5. 90일 실행 계획

### 0~14일 — 안전한 배포

- 신규 migration을 별도 환경에 적용하고 RLS·service-role 전용 접근을 확인한다.
- `CRON_SECRET`, 실제 연락처가 포함된 `SEC_USER_AGENT`, 가능하면 등록된 `BLS_API_KEY`를 설정한다.
- 유료 스케줄러는 사용하지 않는다. Vercel Hobby에는 일 1회 작업만 남기고, 30분 공식 피드와 BLS 발표창 수집은 Supabase `pg_cron + pg_net + Vault`로 실행한다.
- `/intelligence`의 인증된 온디맨드 갱신은 30분 쿨다운을 적용해 무료 API·함수 사용량을 보호한다.
- `cron.job_run_details`는 30일만 보존하고 Supabase DB 500 MB, Vercel Function 호출량을 월별 점검한다.
- 7일간 shadow 운영하며 누락, 중복, 원천별 p95 지연, 빈 payload를 기록한다.
- Data Health 경보와 수집 kill switch를 추가한다.

### 15~30일 — 포트폴리오 연관성

- SEC/OpenDART entity master와 holdings/watchlist mapping을 구축한다.
- 실적·공시·거래정지·통화정책·고용/물가 이벤트를 포트폴리오 레이더에 연결한다.
- 알림을 `즉시 확인`, `오늘 확인`, `정보` 세 단계로 제한해 과도한 알림을 막는다.
- PLANNED 위험 예약과 ENTRY 재검증을 DB 트랜잭션으로 완성한다.

### 31~60일 — 분석 품질

- consensus provider를 선정하고 actual/consensus/previous/revision을 point-in-time으로 저장한다.
- deterministic extraction 결과와 LLM 요약을 분리 저장한다.
- 원문 근거 없는 숫자·방향·티커를 생성한 LLM 결과는 자동 폐기한다.
- 사건 유형별 1일/5일/20일 event study와 false-alert rate를 측정한다.

### 61~90일 — 모델 승격

- 최소 8주 shadow 결과와 과거 walk-forward를 결합한다.
- regime·시장·시가총액별 성능 및 최대낙폭 악화를 확인한다.
- 투자위원회 승인 전까지 인텔리전스는 advisory로 유지한다.
- 승인된 규칙만 포지션 위험 배수에 단계적으로 연결하고 즉시 해제 가능한 kill switch를 둔다.

| 항목 | 초기 목표 |

| 공식 RSS 수집 지연 | 발표 후 p95 7분 이내 |
| BLS release 관측 | 예정 발표 후 10분 이내 |
| stale/failed 원천의 READY 오판 | 0건 |
| 동일 revision 중복 저장 | 0.1% 미만 |

| 고중요도 alert precision | shadow 표본에서 80% 이상 |
| 추천 공식 발행 검증 커버리지 | 100% |

모델 승격은 단일 수익률이 아니라 데이터 누락률, calibration, 비용 후 expectancy, MDD, turnover, regime 안정성을 함께 본다. 기준을 통과하지 못한 기능은 제거하지 않고 `RESEARCH_ONLY` 또는 `SHADOW` 상태로 유지한다.

## 7. 운영 원칙

- 투자 성공은 보장할 수 없으며, 목표는 기대값을 높이고 치명적 손실·데이터 오판을 줄이는 것이다.
- 뉴스 제목의 긍정/부정을 곧바로 매수/매도 신호로 바꾸지 않는다.
- 원천 데이터와 분석 결과를 같은 필드에 덮어쓰지 않는다.
- 실패 시 마지막 값을 최신처럼 재사용하지 않는다. 사용해야 한다면 `STALE/FALLBACK`을 명시하고 신규 진입을 차단한다.
- 외부 부수효과는 `DRY_RUN=true`와 kill switch를 지원한다.
- 모델·정책·프롬프트 변경은 버전, 변경 사유, 검증 결과, 승인자를 보존한다.

## 8. 배포 완료 조건

- [ ] 신규 migration만 적용되는지 pending migration 목록을 검토했다.
- [ ] anon/authenticated가 이벤트 원장을 직접 읽거나 쓸 수 없다.
- [ ] cron 무인증 요청은 401이고 올바른 secret 요청만 성공한다.
- [ ] FED/BOK/SEC/BLS 각각 실제 endpoint smoke가 성공한다.
- [ ] 한 원천 실패, 빈 RSS, 오래된 BLS, 중복 cron을 주입해 `BLOCKED`/멱등성을 확인한다.
- [ ] macro `BLOCKED`가 50점 정상 snapshot으로 저장되지 않는다.
- [ ] 추천 게이트 일부 실패가 공식 추천으로 발행되지 않는다.
- [ ] 동시 매매 계획과 ENTRY가 위험예산을 초과하지 않는다.
- [ ] 전체 lint, typecheck, unit, API auth, production build가 통과한다.
